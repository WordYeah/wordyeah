# WordYeah 长期开发与维护约定

WordYeah 是公司内容审核链路中的长期项目。本文定义代码、模型、策略、数据和审核台的维护边界；具体接口、部署命令和验收指标分别以 `API.md`、`DEPLOYMENT.md` 和 `ACCEPTANCE.md` 为准。

## 1. 服务目标

- 默认由 AI 完成快速扫描、一审和独立二审，只把最终不确定项交给人工。
- 图片审核先服务 Cravatar 与 Gravatar 镜像，后续文字、视频和音频继续使用同一结果、任务、审核和审计合同。
- 自管模型与自管 G2A Web 号池承担审核，不恢复腾讯云或其他第三方内容审核 API。
- 模型失败、证据缺失、状态无法解释时必须留置，不能转成 `allow`。
- 生产数据接入与生产处置分离：先只读 Shadow，生产写回必须另行评审和授权。

## 2. 代码边界

| 模块 | 职责 | 不应承担 |
| --- | --- | --- |
| `wy_core` | 结果合同、策略、数据库、指标 | 来源系统专用逻辑 |
| `wy_media` | 图片安全、快速模型、高级视觉 provider | 生产头像写回 |
| `wy_word` | 文本规则及后续语义审核 | 图片下载和解码 |
| `wy_jobs` | 持久任务、lease、重试、worker | 覆盖历史 attempt |
| `wy_review` | 路由、队列、质量、双审、仲裁 | 把 AI 建议当真人真值 |
| `wy_cravatar` | Cravatar/Gravatar 来源适配、游标和 Shadow | 通用审核策略 |
| `wy_api` | API、reviewer session、审核台 | 绕过领域层直接改最终状态 |

跨模块共享字段必须先更新合同、迁移、API 文档和兼容测试；来源适配器不得把 Cravatar 特有状态写进通用结果枚举。

## 3. 数据分类与保留

| 数据 | 默认位置 | 维护要求 |
| --- | --- | --- |
| 原始/规范化媒体 | SQLite 外的受控目录 | 0700 目录、0600 文件、固定根目录、内容哈希校验 |
| submission、finding、attempt、事件 | SQLite WAL | 追加审计；最终结论不得静默覆盖 |
| cursor、失败账本、水位 | 独立原子 JSON | 可暂停、恢复、幂等重跑；禁止日常删除或倒带 |
| reviewer 凭据、G2A/Ollama 配置 | 仓库外运行时配置 | 不进入 Git、文档、日志、截图和审核事件 |
| 质量 corpus | 私有 reviewer 目录 | AI 建议与人工真值分表；双审身份独立 |

媒体和审计记录的实际保留期限在启用生产处置前确定。删除批次、媒体或审计数据必须先生成逐项清单、确认备份和取得授权。

## 4. 变更分类

### 普通代码变更

- 保持现有结果枚举、fail-closed 和 `enforce=false`。
- 修改同一模块的实现与直接测试，不顺手重构其他模块。
- API、环境变量、CLI 参数或页面交互变化必须同步文档。

### 模型或提示词变更

- 固定 provider、模型、提示词和策略版本，旧 attempt 保持可追溯。
- 先离线回放冻结 corpus，再做受控 canary；不能只用合成图片或单个成功响应替代质量验收。
- 比较自动拒绝精确率、违规召回率、自动通过漏审率、二审率、人工升级率、延迟和错误率。
- 新版本不达门槛时回退配置并保留失败证据，不改写旧结果。

### 策略变更

- 阈值、类别映射、抽检率、批量上限和特殊风险规则必须版本化。
- 策略变更只影响新任务；历史结果按原策略版本解释。
- 自动通过、自动拒绝、黑名单和生产写回是独立开关，不得合并放量。

### 数据来源变更

- 新来源使用独立 adapter、workspace 和 consumer。
- 必须记录来源 ID、来源引用、采集时间、内容 SHA-256 和当前内容身份。
- 来源数据库默认只读；下载地址必须进入 allowlist，不能接受调用方任意 URL。

## 5. 分支、提交与评审

- 一次提交只包含一个可解释的行为变化；代码、测试和对应文档一起提交。
- 不提交 `var/`、私有数据库、媒体、模型、凭据、浏览器 storage state 或本地产物。
- 审核台变更必须同时做桌面和移动端真实浏览器复核；几何无溢出不等于视觉通过。
- 生产数据、生产调度、模型路由、权限或保留策略变化必须单独评审，不夹在 UI 或常规修复提交中。

## 6. 验证矩阵

| 变更范围 | 最低验证 |
| --- | --- |
| Python 逻辑 | 直接相关 pytest、完整 pytest、Ruff、compileall、`git diff --check` |
| API/数据库 | 正向、错误路径、幂等、重启/lease、迁移兼容 |
| provider/worker | 真实 canary、超时、429/5xx、无效响应、fallback、错误不放行 |
| 审核台 | 1440、1280、760、390px；九页面、全部下拉、列表/网格/沉浸、详情与动作 |
| Cravatar 接入 | 只读源核对、暂停/恢复、重跑无新增、失败账本、生产零写入 |
| 生产候选版本 | 聚合验收；任何 `SKIP`/`INCOMPLETE` 不得写成通过 |

## 7. 发布与回滚

发布前必须记录代码提交、数据库 schema、策略版本、模型版本、运行配置指纹和验收报告。部署顺序为数据库备份、API、快速 worker、高级视觉 worker、只读数据 runner；每一步验证后再继续。

回滚优先停止入口或 worker、恢复上一版只读配置和代码，不删除 cursor、任务、attempt 或事件。模型和策略回滚只影响新任务；已经产生的结论保留原版本信息。生产写回一旦启用，必须另有来源系统级别的逐项回滚方案。

## 8. 日常维护

- 每日：检查 ready、队列深度、最老任务、失败/死信、G2A/Ollama 错误和人工升级量。
- 每周：检查数据库/WAL、磁盘、备份可恢复性、游标水位、重复任务和错误路径放行数。
- 每月：抽检自动通过/拒绝、检查模型和策略漂移、复核权限、依赖和保留数据。
- 事故后：保留批次、cursor、任务、attempt、模型响应摘要和事件；先停止放量，再定位来源、模型、策略或审核动作，不清理证据。

## 9. 文档职责

- `README.md`：项目入口和文档索引。
- `STATUS.md`：已经实现、已经验证和仍未完成的事实。
- `HANDOFF.md`：当前运行任务、未完成项、恢复入口和不可突破的边界；运行数字必须标注快照时间。
- `API.md`：接口与鉴权合同。
- `REVIEW_WORKBENCH.md`：AI 多级审核和人工交互合同。
- `ONLINE_DATA_RUNBOOK.md`：在线只读数据接入与分阶段放量。
- `DEPLOYMENT.md`：主机目录、服务和部署边界。
- `ACCEPTANCE.md`：质量、安全、负载和浏览器门槛。
- `CRAVATAR_FULL_REGISTRY_REVIEW_PLAN.md`：首次全量历史审核计划，不构成执行授权。
- `adr/`：会影响长期实现方向且已经确定的决策。

文档中的计划、样本、结构检查和只读 canary 都不能替代实际完成证据；事实变化时同时更新 `STATUS.md`，不要在多份文档中复制不同版本的状态数字。
