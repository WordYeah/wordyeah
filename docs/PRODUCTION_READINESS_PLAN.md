# WordYeah 头像审核生产接入计划

日期：2026-08-09

## 目标和边界

目标是让 WordYeah 接管 Cravatar 与 Gravatar 镜像头像的自动审核、AI 二审、少量人工复核和可审计处置。开发阶段继续保持 `enforce=false`；生产头像、WordPress、Cavalcade 和远程数据库写入必须经过单独批准与回滚演练。

## 实施顺序

### P1 Reviewer 账户与 Cravatar 头像

- 增加用户名、显示名称、邮箱、角色和允许工作区资料。
- 认证 secret 与账户资料分开配置；日志和 HTML 不输出 token。
- 服务端规范化邮箱并计算 MD5，浏览器只接收 `cn.cravatar.com/avatar/<md5>`，不发送原始邮箱给头像服务。
- 顶栏、账户菜单和账户页使用同一份资料；无邮箱时使用文字头像。
- 验收：资料校验、HTML 转义、CSP、移动端弹层、登录和退出回归。

### P2 权限与会话

- 按 reviewer 角色限制审核、仲裁、策略查看和工作区切换。
- 会话记录真实建立时间、最近活动、到期时间和撤销状态。
- 高风险操作保留 CSRF、乐观锁和追加审计。

实现状态（2026-08-09）：服务端已按账户资料限制可见工作区及工作区切换；普通审核、
高级审核、仲裁和黑名单动作已分别进行角色校验。启用任意 reviewer profile 后，缺少资料的
登录账户按 fail-closed 拒绝访问。审核会话已写入 SQLite 账本，登录记录建立时间、最近活动、
到期时间和 IP 哈希，退出时撤销当前会话；账户页展示最近 20 条会话及状态。策略页的细粒度
只读权限仍与 P3 的运行配置一起验收，不影响现有审核动作的服务端权限边界。

### P3 全量只读接入

- 先导入 1,000，再按 10,000、100,000 和全量逐级放量。
- Cravatar 与 Gravatar 镜像都进入同一审核合同，来源只作为 provenance。
- 每阶段核对游标、去重、失败账本、吞吐、模型错误、队列年龄和源库零写入。

实现状态（2026-08-09）：已实现登记表 `image_md5` keyset 导出、旧域名输入规范化、无效
metadata 留置、内容地址存储，以及 `registry_snapshots`、`registry_assets`、`content_assets`
本地账本。1,000 条只读 canary 已形成 1,000 条来源终态：963 collected、27 invalid_metadata、
10 fetch_missing；963 条来源映射到 960 个唯一内容，已向本地 WordYeah 提交 960 条且失败 0，
幂等重跑新增 0。生产业务字段前后语义摘要一致，生产数据库和头像写入均为 0。

该批整体仍为 `INCOMPLETE`：整批 AI 处理未到终态，首轮采集缺少完整延迟分位数，只记录了
27 条重试的 p50=285ms、p95=725ms。因此不授权 10,000 条阶段；需先用同一版代码完成有完整
延迟、队列和模型指标的有界样本。首次提交还发现 active job 达到 1,000 时部分项目被留置但
客户端收到成功；现已改为 HTTP 429 背压，并只对 `vision_queue_full` 留置项做幂等恢复。

### P4 质量门槛

- 完成冻结 1,100 条 corpus 的人工主审、固定 10% 独立双审和分歧仲裁。
- 按真人、动漫、logo/文字、边界和明确违规分别计算误杀、漏放和人工介入率。
- 阈值未达标时只允许 Shadow，不开启生产处置。

### P5 部署和运行保障

- 在目标主机安装 API、普通视觉 worker、高级视觉 worker 和 Cravatar 增量采集服务。
- 增加健康检查、队列水位、模型超时、租约、磁盘、失败率和成本告警。
- 完成备份恢复、进程重启、模型不可用、G2A 不可用和 Ollama 回退演练。

### P6 生产处置适配器

- 将 `allow/reject/default-avatar/blacklist/hold` 映射成明确 proposal。
- 写回进程与审核进程隔离，使用最小权限凭据、幂等键、版本校验和逐项审计。
- 先只写内部 proposal，再做小流量 canary；黑名单和不可逆操作必须有独立门槛。
- 通过回滚验证和人工批准后，才允许修改 `enforce=false` 边界。

## 完成判据

- Reviewer 真实资料、权限、会话和 Cravatar 头像均由后端提供，不由 UI 猜测。
- 全量来源可重复采集且不会重复建任务，失败可重放。
- 代表性 corpus 人工真值与双审完成，误杀和漏放达到批准阈值。
- 服务在目标主机持续运行，故障演练、监控和回滚均有证据。
- 生产写回有独立适配器、最小权限、幂等、审计、canary 和明确授权。
