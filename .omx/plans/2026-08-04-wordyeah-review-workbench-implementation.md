# WordYeah 头像审核工作台实施计划

日期：2026-08-04
依据：`.omx/artifacts/wordyeah-design-audit-20260804T103557Z.md`
范围：先完成头像图片审核；文本、OCR、视频、音频只预留边界，不在本轮实现。

## 1. 产品原则

- AI Agent 完成常规判定、排序、解释、重试建议和低风险批处理建议。
- 人工只处理低置信度、模型分歧、错误、抽检和仲裁。
- 每一次自动或人工状态变化都生成独立事件；失败不默认通过。
- 原图不进入 SQLite；审核证据通过受控引用访问。
- 当前不改变 Cravatar 生产头像，不启用 enforce。

## 2. 里程碑

验收：审查报告、任务计划和现有测试结果可复核。

### R1 — P0 正确性与安全证据（1.5–2.5 日）

- [x] 合法图片进入 review/block 队列前生成规范化受控预览；畸形图片进入 held/error 且明确无预览原因。
- [ ] 为 submission/job 增加幂等键；相同 consumer + hash + policy/model 不重复运行。
- [ ] 将 retry 改为新的 review attempt：重新排队模型任务，保存新 evidence snapshot 和版本关系。
- [x] 修复真实 logout；HTML 会话过期跳登录页，API 保持 401。
- [ ] 为 401/403/409/媒体失效增加可恢复页面或工作台提示。

验收：合法待审图片 100% 可预览；重复请求不重复运行；retry 有新 attempt；退出和会话过期浏览器流程通过。

### R2 — 队列与单项审核主流程（2–3 日）

- [ ] 服务端 cursor 分页、排序和筛选；禁止一次拉 1000 条后本地处理。
- [ ] 队列划分：人工必审、模型错误、模型分歧、SLA 超时、抽检、仲裁。
- [x] 队列行展示缩略图、风险、AI 建议、核心证据、等待时间、状态。
- [x] 详情使用独立 focus 视图；返回时保留服务端筛选参数。
- [ ] 图片查看器支持缩放、平移、适配、旋转、模糊/揭示、区域框和证据裁剪。
- [ ] 固定决策栏、结构化原因、备注规则、上一条/下一条和下一条预取。
- [ ] 键盘快捷键及输入框保护。
- [x] 三种队列模式：紧凑列表、视觉网格、快速标记；URL 保留视图和筛选语境。
- [x] 显式批量选择和批量工具条；单批最多 50 项，后端逐项校验版本、逐项审计并报告部分失败。
- [x] 紧凑列表降低单行高度，桌面首屏优先容纳更多例外项。

验收：20、100、1000 条队列下操作稳定；常用审核不依赖长页面滚动；键盘可完成完整单项审核。

### R3 — 审核业务合同（2–4 日）

- [ ] 独立 reviewer 身份和权限范围；不再共享唯一 actor。
- [x] review item 增加 stage、final decision、assignee、claim/lease、due_at 和 attempt 数据结构。
- [x] attempt 增加 reason、policy/model id/version、evidence 和 retry parent 数据结构。
- [ ] 增加 10% sampled QC、second review、disagreement、arbitration。
- [ ] 增加 appeal/recheck，不覆盖原始 decision 与 evidence。
- [ ] 增加 false-positive、false-negative、overturned reason 和 drift 反馈。

验收：双人复核无同人重复；分歧必进仲裁；所有状态转换可追踪；满足 `docs/ACCEPTANCE.md` 的 10% 抽检要求。

注意：身份来源、角色权限和多 consumer 默认行为属于权限模型决策，实施前单独确认；其余 schema 先按单 consumer 可扩展结构实现。

### R4 — 独立页面与信息架构（2–3 日）

- [x] `/review` 审核队列。
- [x] `/review/history` 追加式操作与审计历史（过滤和导出待补）。
- [x] `/review/policies` 生效阈值和路由条件（版本 diff 待补）。
- [x] `/review/health` 模型、队列和错误状态。
- [x] `/review/quality` 抽检、分歧和仲裁只读视图。
- [x] `/review/account` reviewer、consumer、会话和退出。
- [x] `/review/guide` 审核原则、类别和快捷键。

验收：侧栏没有假链接或 disabled 假入口；每个页面可深链、刷新和返回。

### R5 — AI Agent 自动化边界（1.5–2.5 日）

- [ ] Agent 只对策略明确且低风险条目提出批处理建议。
- [ ] 批处理设置数量上限、抽检率、策略版本锁和超时。
- [ ] 后端逐项执行并逐项写事件；部分失败不伪造整体成功。
- [ ] 模型错误、策略漂移、低置信度和异常增长自动停止批处理。
- [ ] 人工能够看到建议来源、影响范围和回退记录。

验收：批量操作可中断、可审计、可部分回滚；Agent 不能绕过 policy、身份和事件记录。

### R5.1 — 结构化反馈与样本留存（2–3 日）

- [ ] 建立版本化受控标签词表；原因码与自由备注分离。
- [ ] 增加误报、漏报、模型分歧、边界样本、需要复训和质量抽检事件。
- [ ] 增加留样候选、已留样、已入样本集三态和追加式事件。
- [ ] 默认只留哈希、决策和证据元数据；原图不默认长期留存。
- [ ] 受控派生样本记录授权来源、用途、TTL、近重复组、split 和复核人数。
- [ ] 区域框选只放入申诉/争议/样本实验室，不进入普通头像审核主路径。

验收：标签可审计且不替代最终决定；媒体过期后元数据仍可追踪；近重复组不会跨数据集 split。

- [ ] 更新 `docs/REVIEW.md`、`docs/API.md`、`docs/ACCEPTANCE.md` 和状态文档。

## 3. 依赖顺序

```text
R0 -> R1 -> R2 -> R3 -> R4 -> R5 -> R6
             \------ R4 的只读页面可与 R3 后半并行
```

先修正确性和证据，再做大范围视觉与页面扩展。Reviewer 身份和权限模型在 R3 开始前确认，不阻塞 R1/R2 的单 consumer 实施。

## 4. 预计工期

- 内部可用头像审核台：10–15 个开发日。
- 加完整抽检、仲裁、独立身份和 Agent 低风险批处理：累计 14–20 个开发日。
- 真实数据指标与 shadow 观察时间另计，不以开发完成替代数据门槛。

## 5. 每阶段最低验证

```bash
PYTHONPATH=src python3 -m unittest discover -s tests -v
python3 -m compileall -q src scripts
ruff check src tests scripts
git diff --check
```

涉及浏览器交互的阶段还必须运行 Playwright 和三档截图基线。
